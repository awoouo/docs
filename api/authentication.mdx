ACS API 采用基于 API 密钥的 Bearer Token 认证机制。每一次 API 请求都必须在 HTTP 请求头中携带有效的 API 密钥，服务端将以此验证您的身份并确认访问权限。API 密钥与您的 ACS 账号绑定，请务必妥善保管，切勿泄露给未经授权的第三方。

---

## 创建 API 密钥

请按照以下步骤在 ACS 控制台中创建您的第一个 API 密钥：

<Steps>
  <Step title="登录控制台">
    打开浏览器，访问 [https://app.acs.com](https://app.acs.com)，使用您的企业账号登录 ACS 信息中心控制台。
  </Step>
  <Step title="进入 API 密钥管理页">
    登录后，点击右上角的账号头像，选择 **账号设置**，然后在左侧导航栏中点击 **API 密钥**。
  </Step>
  <Step title="新建密钥">
    在 API 密钥页面，点击右上角的 **创建密钥** 按钮，进入密钥创建流程。
  </Step>
  <Step title="填写密钥信息">
    在弹出的对话框中，输入密钥名称。建议按用途或环境命名，例如 `生产集成`、`测试环境` 或 `数据同步服务`，便于日后管理与区分。您也可以选填密钥的有效期，到期后密钥将自动失效。
  </Step>
  <Step title="保存密钥">
    点击 **确认** 后，系统将生成并展示完整的 API 密钥。请立即将密钥复制并存储至安全位置（如密码管理器或加密的环境变量配置文件）。

    <Warning>
      **API 密钥仅在创建时显示一次。** 关闭对话框后，您将无法再次查看完整密钥内容。如果密钥丢失，您需要吊销旧密钥并重新创建。
    </Warning>
  </Step>
</Steps>

## 在请求中使用密钥

获取 API 密钥后，在每次请求时将其添加至 HTTP 请求头的 `Authorization` 字段，格式如下：

```
Authorization: Bearer YOUR_API_KEY
```

以下是一个完整的请求示例，用于获取当前已认证用户的账号信息：

```bash
curl -X GET https://api.acs.com/v1/users/me \
  -H "Authorization: Bearer sk_live_abcdefghij1234567890"
```

<Note>
  请将示例中的 `sk_live_abcdefghij1234567890` 替换为您实际的 API 密钥。在生产环境中，建议通过环境变量注入密钥，而非硬编码在代码中（详见[密钥安全最佳实践](#密钥安全最佳实践)）。
</Note>

## 通过 Token 接口获取访问令牌

除直接在请求头中携带 API 密钥外，您也可以使用 `POST /api/v1/auth/token` 接口，通过 API 密钥换取短效访问令牌（Access Token）。访问令牌适合需要临时授权或对外共享有限访问权限的场景，其有效期默认为 **1 小时**。

**请求示例**：

```bash
curl -X POST https://api.acs.com/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "api_key": "sk_live_abcdefghij1234567890"
  }'
```

**成功响应**（HTTP `200`）：

```json
{
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600
  },
  "meta": {
    "request_id": "req_tok001",
    "timestamp": "2024-01-15T08:00:00Z"
  }
}
```

获取到 `access_token` 后，在后续请求中以相同的 `Authorization: Bearer <access_token>` 格式使用该令牌即可。令牌到期后，请重新调用本接口获取新令牌。

## 密钥类型

ACS API 提供两种类型的密钥，分别对应不同的运行环境：

| 密钥类型 | 前缀 | 用途 |
|----------|------|------|
| 生产密钥 | `sk_live_` | 访问生产环境 API，操作真实业务数据，请谨慎使用 |
| 测试密钥 | `sk_test_` | 访问沙箱环境 API，适用于开发调试，数据与生产环境完全隔离 |

使用测试密钥时，请将请求发送至沙箱环境 Base URL：`https://sandbox.api.acs.com/v1`。测试密钥无法访问生产环境接口，生产密钥同样无法用于沙箱环境。

## 管理密钥

您可以在 ACS 控制台的 **账号设置 → API 密钥** 页面对所有密钥进行统一管理，支持以下操作：

- **查看所有密钥**：列表展示账号下已创建的全部密钥，包括名称、类型、创建时间与最后使用时间。出于安全考虑，密钥内容仅显示前几位字符，其余部分以星号遮掩。
- **吊销密钥**：当密钥不再使用或疑似泄露时，可立即吊销该密钥。吊销操作不可撤销，已吊销密钥将立即失效，所有使用该密钥的请求将收到 `401` 错误。
- **设置有效期**：在创建密钥时或创建后，可为密钥设置具体的到期日期。密钥到期后将自动失效，适合为临时性集成或外部合作伙伴创建限时访问权限。
- **标注密钥用途**：通过为密钥添加描述性名称，清晰标记其使用场景（如"CRM 系统集成"、"自动化报表任务"），方便团队协作管理与审计。

## 密钥安全最佳实践

妥善保管 API 密钥是保障您账号与数据安全的关键。请遵循以下最佳实践：

- **切勿将密钥提交至版本控制系统**：不要将 API 密钥硬编码在源代码中，也不要将包含密钥的 `.env` 文件提交至 Git 仓库。建议在 `.gitignore` 中添加 `.env`。
- **使用环境变量存储密钥**：将密钥存储在操作系统或部署平台的环境变量中，通过代码读取，避免密钥暴露在源码层面。
- **为每个集成创建独立密钥**：不同的应用或服务使用不同的 API 密钥，一旦某个密钥泄露，可以精准吊销，不影响其他服务的正常运行。
- **定期轮换密钥**：对于长期运行的集成，建议每隔 90 天或根据公司安全策略定期更新 API 密钥。
- **为临时集成设置有效期**：与外部合作方或临时项目共享访问权限时，务必为密钥设置到期日期，到期自动失效，无需手动吊销。

以下示例展示了如何通过环境变量安全地使用 API 密钥：

```bash .env
ACS_API_KEY=sk_live_your_key_here
```

```python
import os
import requests

api_key = os.environ.get('ACS_API_KEY')
headers = {'Authorization': f'Bearer {api_key}'}
response = requests.get('https://api.acs.com/v1/applications', headers=headers)

if response.status_code == 200:
    data = response.json()
    print(data)
else:
    print(f"请求失败，状态码：{response.status_code}")
    print(response.json())
```

## 认证错误处理

认证相关的错误主要涉及 `401 Unauthorized` 与 `403 Forbidden` 两种状态码，二者含义不同，需区别处理：

- **`401 Unauthorized`**：表示请求中未提供 API 密钥，或提供的密钥无效、已过期、已被吊销。请检查 `Authorization` 请求头是否正确设置，并确认密钥处于有效状态。

  ```json
  {
    "error": {
      "code": "unauthorized",
      "message": "API 密钥无效或已过期",
      "request_id": "req_xyz789"
    }
  }
  ```

- **`403 Forbidden`**：表示 API 密钥本身有效，但当前密钥所属账号没有权限访问所请求的资源。例如，尝试访问其他组织的数据，或执行超出当前账号权限范围的操作。请联系您的管理员确认账号权限配置。

  ```json
  {
    "error": {
      "code": "forbidden",
      "message": "您没有权限访问该资源",
      "request_id": "req_xyz790"
    }
  }
  ```

在排查认证问题时，请将响应中的 `request_id` 提供给 ACS 技术支持团队，以便快速定位问题。

<Tip>
  认证成功后，请注意 API 的请求频率限制，避免因超频导致请求被拒绝。详见 [API 概览 → 请求频率限制](/api/overview#请求频率限制)。
</Tip>

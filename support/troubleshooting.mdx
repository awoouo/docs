本指南帮助您系统地诊断并解决使用 ACS 信息中心过程中遇到的常见技术问题。建议您按照各节的排查步骤逐一验证，通常可在几分钟内定位并解决问题。如果按照本指南操作后问题仍未解决，请前往[联系我们](/support/contact)页面提交工单，并附上相关错误截图和 `request_id`，以便支持团队快速跟进。

<Tip>
  在开始排查前，请先访问 [ACS 状态页面](https://status.acs.com) 确认当前是否存在已知的服务故障或维护窗口。如果状态页面显示异常，请等待官方公告，无需重复排查本地配置。
</Tip>

## 登录与认证问题

### 登录失败

如果您在登录时遇到"账号或密码错误"提示，请依次检查以下几点：

<Steps>
  <Step title="确认邮箱地址正确">
    检查输入的邮箱是否为注册时使用的地址，注意大小写及有无多余空格。
  </Step>
  <Step title="确认密码正确">
    尝试在密码输入框中切换"显示密码"，确认输入内容无误。如果使用了密码管理工具，确保其填充的是 ACS 对应账号的密码。
  </Step>
  <Step title="使用无痕模式测试">
    打开浏览器无痕（隐私）窗口，重新尝试登录。这可以排除浏览器扩展、缓存或 Cookie 干扰的问题。
  </Step>
  <Step title="检查账号是否被锁定">
    连续输错密码 5 次后，账号将被暂时锁定。请参阅下方"账号被锁定"部分处理。
  </Step>
</Steps>

### 账号被锁定

为保护账号安全，连续输入错误密码 **5 次**后，账号将被自动锁定 **15 分钟**。锁定期间任何登录尝试均会失败，即使密码正确也无法登录。

**解决方法：**

- **等待解锁**：15 分钟后系统将自动解除锁定，届时可重新尝试登录。
- **联系管理员**：如果您无法等待，可请工作空间管理员在后台手动解除锁定。
- **重置密码**：使用忘记密码流程重置密码，重置操作会同时解除锁定状态。

<Warning>
  若您怀疑账号被他人恶意尝试登录，请在解锁后立即修改密码，并前往 **设置 → 安全 → 登录记录** 检查异常登录活动。
</Warning>

### 忘记密码

<Steps>
  <Step title="打开重置页面">
    访问 ACS 信息中心登录页，点击 **忘记密码？** 链接。
  </Step>
  <Step title="输入注册邮箱">
    在跳转页面中输入您的注册邮箱地址，点击 **发送重置邮件**。
  </Step>
  <Step title="查收邮件">
    在收件箱（或垃圾邮件文件夹）中找到来自 `noreply@acs.com` 的邮件，点击 **重置密码** 按钮。重置链接有效期为 **30 分钟**。
  </Step>
  <Step title="设置新密码">
    按页面提示输入新密码（至少 8 位，包含大小写字母和数字），保存后用新密码登录即可。
  </Step>
</Steps>

## API 错误排查

### 401 Unauthorized

收到 `401` 响应表示身份认证失败，请检查以下几项：

<AccordionGroup>
  <Accordion title="API 密钥是否正确">
    确认您使用的密钥字符串完整无误，没有多余空格或截断。建议直接从控制台复制密钥，避免手动输入。
  </Accordion>
  <Accordion title="密钥是否已过期或被撤销">
    前往 **设置 → API → 密钥管理**，确认密钥状态为"有效"。如果密钥已被撤销或设置了到期时间，需要重新创建。
  </Accordion>
  <Accordion title="Authorization 请求头格式是否正确">
    ACS API 要求以 `Bearer` 方案传递密钥，格式如下：

    ```http
    Authorization: Bearer YOUR_API_KEY
    ```

    常见错误包括：缺少 `Bearer ` 前缀、多余的引号，或误用了 `Token` 等其他前缀。
  </Accordion>
</AccordionGroup>

### 403 Forbidden

收到 `403` 响应表示身份已验证，但您没有执行该操作的权限，请检查：

- **工作空间成员资格**：确认您的账号已被添加至目标工作空间。
- **角色权限**：不同角色（查看者、编辑者、管理员）的 API 操作权限不同，请联系工作空间管理员确认您的角色。
- **资源归属**：部分接口仅允许资源的创建者或所有者访问，请确认操作对象的归属。

### 429 Rate Limited

收到 `429` 响应表示您在当前时间窗口内的调用次数已达上限。

**查看剩余配额：** 每次 API 响应均包含以下请求头，可用于监控使用情况：

```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 42
X-RateLimit-Reset: 1720000000
```

`X-RateLimit-Reset` 为 Unix 时间戳，表示配额重置时间。

**建议的应对策略：**

- 在客户端缓存不频繁变化的响应数据，减少重复请求。
- 对批量操作使用指数退避（Exponential Backoff）重试策略。
- 评估是否需要升级套餐以获得更高调用配额。

### 使用 curl 调试 API 请求

当您需要排查网络层或请求格式问题时，可以使用 `curl` 的详细模式查看完整的请求和响应信息：

```bash
curl -v -X GET https://api.acs.com/v1/users/me \
  -H "Authorization: Bearer YOUR_API_KEY"
```

`-v` 参数会输出完整的请求头、响应头和响应体，帮助您确认：

- 请求是否成功到达服务器
- 实际发送的请求头内容
- 服务器返回的原始错误信息和 `request_id`

<Tip>
  响应体中的 `meta.request_id` 字段是联系支持时最重要的信息，支持团队可通过它快速查到服务端日志，大幅缩短排查时间。
</Tip>

## 应用入口问题

### 应用无法打开

如果点击应用图标后无响应或页面报错，请按以下步骤排查：

<Steps>
  <Step title="检查应用状态">
    访问 [ACS 状态页面](https://status.acs.com)，确认目标应用是否处于维护或故障状态。
  </Step>
  <Step title="检查本地网络">
    确认您的网络连接正常，可尝试访问其他网站确认。如在公司内网环境，请确认网络策略允许访问该应用的域名。
  </Step>
  <Step title="使用无痕模式测试">
    打开浏览器无痕窗口后重新访问，排除浏览器插件（如广告拦截器）或缓存问题的干扰。
  </Step>
  <Step title="清除浏览器缓存">
    如无痕模式下可正常访问，请清除浏览器缓存和 Cookie 后重试。
  </Step>
</Steps>

### 权限被拒绝

如果访问应用时提示"无权限"或"Access Denied"，说明您的账号尚未获得该应用的访问授权：

1. 在应用卡片上点击 **申请权限**，填写申请理由并提交。
2. 系统将通知您的工作空间管理员审批，审批通过后您会收到邮件提醒。
3. 如果情况紧急，可直接联系管理员加急处理。

### 应用加载慢

如果应用可以打开但加载速度异常缓慢：

- **查看状态页**：访问 [https://status.acs.com](https://status.acs.com) 确认是否有已知的性能降级通知。
- **检查自身网络**：使用测速工具（如 speedtest.net）测试当前网络带宽和延迟。
- **尝试其他网络**：切换至移动热点或不同 Wi-Fi 网络，判断是否为本地网络问题。
- **联系支持**：如果持续缓慢且状态页显示正常，请提交工单并附上应用名称、出现时间及所在地区，方便支持团队进一步排查。

## Webhook 问题

### Webhook 未收到

如果您配置了 Webhook 但未收到预期的事件推送：

<AccordionGroup>
  <Accordion title="确认端点可公开访问">
    Webhook 端点必须可以从公网访问，`localhost` 或内网地址无效。您可以使用 [webhook.site](https://webhook.site) 等工具临时接收请求，验证 ACS 的推送是否正常到达。
  </Accordion>
  <Accordion title="检查 Webhook 投递日志">
    前往 **设置 → Webhooks**，点击对应 Webhook 条目的 **投递日志**，查看每次触发的请求状态码和响应内容。如果显示连接超时或 5xx 错误，说明是端点侧的问题。
  </Accordion>
  <Accordion title="确认订阅了正确的事件类型">
    在 Webhook 配置页面确认已勾选您需要监听的事件类型，未订阅的事件不会推送。
  </Accordion>
  <Accordion title="端点响应时间是否过长">
    ACS 要求 Webhook 端点在 **10 秒**内返回 `2xx` 响应，否则视为投递失败并进行重试。建议在收到请求后立即返回 `200 OK`，再异步处理业务逻辑。
  </Accordion>
</AccordionGroup>

### 签名验证失败

ACS 在每次 Webhook 推送时，会在请求头中附上 `X-ACS-Signature` 签名，用于验证请求来源的合法性。签名验证失败最常见的原因是**使用了解析后的 JSON 对象**计算签名，而非原始请求字节流。

**正确的验证方式：**

1. 读取 HTTP 请求的**原始字节体**（Raw Body），不要对其进行任何解析或格式化。
2. 使用 Webhook 配置页面上显示的**签名密钥**（Signing Secret），通过 HMAC-SHA256 算法计算签名。
3. 将计算结果与请求头中的 `X-ACS-Signature` 进行对比，匹配则验证通过。

<Warning>
  JSON 序列化库在反序列化后再序列化时，可能改变字段顺序或空白字符，导致签名结果不一致。务必在任何解析操作之前保存原始请求体。
</Warning>

### 重复收到事件

在网络不稳定或端点响应超时的情况下，ACS 会对未成功投递的事件进行重试，这可能导致您的端点多次收到同一事件。

**解决方法：使您的 Webhook 处理器具备幂等性。**

每个 Webhook 事件的 payload 中均包含唯一标识字段 `evt.id`，建议您：

1. 收到事件后，先检查数据库或缓存中是否已处理过该 `evt.id`。
2. 若已处理，直接返回 `200 OK` 跳过业务逻辑。
3. 若未处理，执行业务逻辑并将 `evt.id` 标记为已处理。

这样无论 ACS 重发多少次，您的业务数据都不会受到影响。

## 获取支持

如果您已按照本指南逐步排查，问题仍未解决，请前往[联系我们](/support/contact)页面通过工单、邮件或在线聊天联系 ACS 技术支持团队。提交时请尽量提供以下信息，以加快处理速度：

- 详细的问题描述和复现步骤
- 相关错误截图或错误信息文本
- API 响应中的 `request_id`
- 您的浏览器版本和操作系统

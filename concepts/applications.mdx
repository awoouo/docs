在 ACS 信息中心中，**应用（Application）**是指通过门户统一纳管、供团队成员访问的各类业务系统。无论是公司内部自研的 OA 系统，还是订阅的第三方 SaaS 工具，抑或是您通过 API 自主接入的定制化系统，都可以作为一个"应用"注册到 ACS 信息中心，从而实现**统一入口访问、集中权限控制和标准化管理**。成员无需记忆多个系统地址，只需登录信息中心，即可在已授权的应用列表中一键直达。

## 应用类型

ACS 信息中心支持接入三类应用，满足不同的业务场景需求：

**内部应用**

指企业自有、部署在内部网络或私有云环境中的业务系统，例如：
- OA（办公自动化）系统
- CRM（客户关系管理）系统
- ERP（企业资源计划）系统
- 内部知识库与文档平台

此类应用通常需要通过企业内网访问，ACS 信息中心将为其提供统一的入口跳转，并可结合单点登录（SSO）进行身份验证。

**外部应用**

指企业订阅或使用的第三方 SaaS 工具，这些工具托管于外部服务商，通过公网访问。例如项目管理工具、在线设计平台、云端数据分析服务等。将其注册到信息中心后，成员可以在同一界面找到所有常用工具的入口，无需在多个标签页之间频繁切换。

**自建应用**

指客户自主开发、通过 ACS 开放 API 注册并集成到信息中心的定制化应用。自建应用支持通过 API 进行全生命周期管理，包括注册、更新配置和下线，适合有深度集成需求的技术团队。

## 注册新应用

<Steps>
  <Step title="进入应用管理页面">
    登录 ACS 信息中心后，在左侧导航栏中点击 **应用（Applications）**，进入当前工作空间的应用管理页面，您可以在此查看所有已注册的应用。
  </Step>
  <Step title="添加新应用">
    点击页面右上角的 **添加应用（Add App）** 按钮，系统将打开应用注册表单。
  </Step>
  <Step title="填写应用信息">
    在注册表单中依次填写以下信息：
    - **应用名称**：为应用起一个清晰易识别的名称，将显示在应用列表中
    - **应用 URL**：填写应用的访问地址，成员点击入口后将跳转至此地址
    - **描述**：简要说明该应用的用途，帮助成员了解其功能
    - **图标 URL**：填写应用图标的图片链接，将显示在应用卡片上（不填则使用默认图标）
    - **访问权限**：选择谁可以看到并访问该应用
  </Step>
  <Step title="保存应用">
    确认所有信息填写无误后，点击 **保存（Save）** 按钮。应用将立即出现在工作空间的应用目录中，具备相应权限的成员可以立即访问。
  </Step>
</Steps>

## 应用配置项

以下是注册或编辑应用时可配置的字段说明：

<ParamField path="name" type="string" required>
  **应用名称** — 应用在信息中心中显示的名称，建议简洁明了，长度不超过 50 个字符。该字段将出现在应用卡片、导航列表及搜索结果中。
</ParamField>

<ParamField path="url" type="string" required>
  **应用 URL** — 应用的完整访问地址，需以 `https://` 或 `http://` 开头。成员点击应用入口时，将在新标签页中跳转至此 URL。
</ParamField>

<ParamField path="description" type="string">
  **描述** — 对应用功能和用途的简要介绍，将显示在应用卡片的悬停提示和详情页中。建议不超过 200 个字符，帮助成员快速了解该应用的作用。
</ParamField>

<ParamField path="icon_url" type="string">
  **图标 URL** — 应用图标的图片链接，建议使用尺寸为 64×64 像素的正方形图片，支持 PNG、JPG、SVG 格式。若不填写，系统将自动使用默认的通用应用图标。
</ParamField>

<ParamField path="access" type="enum">
  **访问权限** — 控制哪些成员可以在应用目录中看到并访问该应用，支持以下三个枚举值：

  - `public`：工作空间内的所有成员均可访问
  - `workspace`：仅已加入当前工作空间的成员可访问（需登录）
  - `admin-only`：仅工作空间管理员可见和访问，适用于管理后台等敏感入口
</ParamField>

## 通过 API 管理应用

对于需要自动化或批量操作的场景，ACS 信息中心提供完整的 REST API，支持通过程序化方式注册和管理应用。以下示例展示如何通过 API 注册一个新应用：

```bash
curl -X POST https://api.acs.com/v1/applications \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "HR 系统", "url": "https://hr.example.com", "access": "workspace"}'
```

请求成功后，API 将返回新创建应用的完整信息：

```json
{
  "id": "app_01HZ93KXPQW4B7MNVR6DTYCEJ",
  "name": "HR 系统",
  "url": "https://hr.example.com",
  "description": null,
  "icon_url": null,
  "access": "workspace",
  "workspace_id": "ws_01HZ91ABCDEF234567890XYZ",
  "created_at": "2024-06-15T08:30:00Z",
  "updated_at": "2024-06-15T08:30:00Z"
}
```

<Note>
  应用归属于创建时所在的工作空间，不同工作空间的应用相互独立、互不可见。通过 API 管理应用时，请确保请求头中使用的 API 密钥属于目标工作空间，否则操作将返回权限错误。如需跨工作空间管理应用，需分别切换工作空间上下文或使用对应工作空间的 API 密钥。
</Note>

工作空间（Workspace）是 ACS 信息中心中最基本的资源组织单元。每个工作空间拥有独立的成员列表、应用目录、API 密钥和配置项，彼此之间完全隔离、互不干扰。无论您管理的是一个小型研发团队，还是跨部门的大型企业组织，工作空间都能帮助您清晰划分边界、精细控制权限，让资源管理变得简单而有序。

## 工作空间的作用

合理使用工作空间，可以为您的团队带来以下核心价值：

- **资源隔离**：不同工作空间的应用、数据与配置相互独立，避免跨团队误操作或数据泄露。
- **成员管理**：每个工作空间维护独立的成员列表，支持按角色分配权限，确保人员职责清晰。
- **API 密钥归属**：API 密钥隶属于特定工作空间，调用行为与计费统计均按工作空间维度独立核算。
- **独立配置**：通知设置、集成配置、域名绑定等均可在工作空间层面单独维护，灵活适应不同业务场景。

## 创建工作空间

<Steps>
  <Step title="登录并进入设置">
    使用您的账号登录 ACS 信息中心。点击页面右上角的用户头像，在下拉菜单中选择 **设置（Settings）**，进入账户管理页面。
  </Step>
  <Step title="新建工作空间">
    在设置页面的左侧导航栏中，找到并点击 **工作空间（Workspaces）** 选项。页面右上角将显示 **新建工作空间（New Workspace）** 按钮，点击后弹出创建对话框。
  </Step>
  <Step title="填写名称并确认">
    在对话框中输入工作空间的名称（建议使用团队名称或环境标识，如"研发团队"或"生产环境"）。确认信息无误后，点击 **创建（Create）** 按钮，系统将立即为您初始化新的工作空间，并自动将您设置为该工作空间的管理员。
  </Step>
</Steps>

## 工作空间成员角色

ACS 信息中心为工作空间内的成员定义了三种标准角色，每种角色对应不同的操作权限：

| 角色 | 权限描述 |
|------|----------|
| **管理员** | 管理成员（邀请、移除、变更角色）、管理应用、创建与吊销 API 密钥，以及修改工作空间的全部配置项 |
| **开发者** | 调用工作空间内的 API 接口、查阅开发者文档、创建和管理自己名下的 API 密钥，以及访问应用目录 |
| **普通用户** | 访问工作空间内已授权的应用入口与文档中心，无法进行任何管理操作 |

<Note>
  每个工作空间至少需要保留一名**管理员**。如果您是当前工作空间的唯一管理员，需先将其他成员提升为管理员后，才能变更自己的角色或离开该工作空间。
</Note>

## 切换工作空间

如果您的账号同时属于多个工作空间，可以通过顶部导航栏快速切换。操作方式如下：

点击顶部导航栏左侧显示的**当前工作空间名称**，系统会展开一个工作空间列表下拉菜单，其中列出您有权访问的全部工作空间。点击目标工作空间的名称，页面将立即切换至该工作空间的上下文，包括应用列表、API 密钥和配置项均同步更新为目标工作空间的内容。

## 删除工作空间

<Warning>
  删除工作空间是**不可逆操作**。工作空间一旦删除，其下的所有应用注册信息、API 密钥、成员关系及配置数据将被永久清除，无法恢复。请在执行此操作前务必做好数据备份，并确认所有成员已知晓。
</Warning>

如需删除工作空间，请按以下步骤操作：

1. 以**管理员**身份进入目标工作空间。
2. 依次点击 **设置（Settings）** → **工作空间（Workspace）** → **高级（Advanced）**。
3. 在"危险操作区"找到 **删除工作空间（Delete Workspace）** 按钮并点击。
4. 在确认弹窗中，输入工作空间的完整名称以进行二次确认，随后点击 **确认删除（Confirm Delete）**。

<Tip>
  建议您为不同的环境分别创建独立的工作空间，例如"开发环境（Dev）"、"预发布环境（Staging）"和"生产环境（Production）"。这样可以彻底隔离测试数据与真实数据，避免因误操作影响线上业务，也便于按环境单独管理 API 密钥和访问权限。
</Tip>
